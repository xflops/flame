## Highlights

Scheduling
- DRF now orders sessions by dominant share and re-balances them toward a desired share. It no longer divides capacity by the number of open sessions, so an idle session no longer limits a busy one (#608). DRF's session ordering was also reversed before this change.
- Gang scheduling uses `batch_size`; `min_instances` is only a floor that keeps instances alive (#591, #593, #599).
- The priority plugin only orders sessions; MinMax owns executor demand (#568). Executor allocation is bounded by demand and by scoped limits (#564, #567).
- Data-aware task routing and instance-level data-aware scheduling (#516, #517, #520).
- Idle executors are reused before autoscaling (#529).

Sessions and applications
- Suspend and resume sessions, and session deletion in `flmctl` and the SDKs (#603, #606, #600).
- Disabled applications are reconciled after their sessions drain (#541, #542).
- Session tokens are passed to instances (#559).
- Per-executor cgroup for the host shim (#604, #609).

Sandbox, CRI and Kubernetes
- `flmbox` sandbox CLI and service, and `flamepy.agent.Sandbox` (#605, #607).
- CRI executor shim, with E2E and benchmark coverage (#526, #527, #528, #530); the CRI instance runtime image is published (#535).
- Kubernetes executor managers run as host-shim DaemonSet workers (#561), GPUs are assigned through executor-manager device managers (#566), and the object cache runs in each executor-manager pod (#595).
- External access and secure object-cache proxying, with client mTLS (#524, #553).
- Images are built on native amd64 and arm64 runners (#563).

Object cache
- Cache reads and writes stream through the storage engine, and each object is stored as append-only files (#585, #586).
- Objects are addressed by their owning cache with `cache.advertise` (#587).
- Opaque bytes over gRPC with typed metadata (#544); stale application cache data is garbage collected (#543).

Python SDK
- `flamepy.app` replaces the Runner API (#537); `flamepy.agent` replaces the tools sandbox (#536); a Sandbox API for remote script execution (#514).
- Async (`aio`) core SDK and async App services (#548); shared session task watches (#549); applications can be packaged for deploy and update (#551).
- Faster cold start of a `flamepy.app` service (#590).

Performance and reliability
- Task and payload writes are no longer fsynced, and only terminal task records are synced (#597, #598); the session manager frontend, backend and scheduler run on dedicated runtimes (#596, #597).
- Filesystem storage locking and session lifecycle fixes, and executor lifecycle transitions published after persistence (#572, #576).
- NVML is initialized once per executor manager (#580).

Tooling
- `flmbench`, a multi-session burst benchmark (#581).
- A `testing/` directory with E2E, system stress and longevity tests, and the `flame-test` image (#582, #583).
- The Python E2E, Rust E2E and Python system test workflows run on both a `priority` and a `drf` cluster (#608).

## Upgrade Notes

- Replace imports of the Runner API with `flamepy.app`, and uses of the tools sandbox with `flamepy.agent` (#537, #536).
- Cache objects are created once and then only appended to: a put to an existing key fails with `AlreadyExist`, and there is no update (#586).
- `cache.advertise` replaces `cache.network_interface`. Configs that still set `network_interface` keep loading (#587).
- Session `min_instances` no longer starts a gang by itself; use `batch_size` for gangs (#599).
- With the `drf` policy, a session may take free capacity beyond its fair share and is trimmed back only when another session needs it. Policies are configured as a list, for example `drf` with `das`.
- The Helm chart `appVersion` and image tags move to `0.7.0-rc1`.

## Known Gaps
